- **User value:** Remote changes appear automatically in the relevant visible resource without manual refresh or duplicated state.
- **Functional scope:** PostgreSQL source of truth; AFTER_COMMIT publication; shared WebSocket transport; Redis fan-out; authorized scopes; eventId dedupe; reconnect/resubscribe/resync; targeted invalidation/refetch; no polling. - **Backend work:** Consolidate publisher/envelope/coordinator/scope authorization and bounded post-commit delivery. Verify rollback isolation, revocation and Redis fallback. Review duplicate Chat/domain registries without destabilizing Chat presence/typing/push suppression.
- **Flutter work:** Central parser/router, reference-counted subscription lifecycle, bounded dedupe, coalesced targeted REST reload, stale/disposed response guards, and reconnect/resume resync. Preserve auth cold-start and deep-link fixes.
- **Database/schema work:** Reuse current persistence; no new migration required by the current invalidation slice. No fabricated aggregate revision. Any future revision/outbox requires a separate justified design/migration decision.
- **Realtime/WebSocket work:** Lock the RSVP contract in [API §41.6](API_CONTRACT_BACKEND_IMPLEMENTATION_BLUEPRINT_v1.0.md#416-uncommitted-activity-rsvp-realtime-vertical-slice): `DOMAIN_CHANGED` envelope with eventId, eventType `ACTIVITY_RSVP_CHANGED`, aggregateType/id, groupId, nullable actorId, activity scope, occurredAt and empty payload. No reliable version exists today: use eventId dedupe plus authoritative refetch/resync; occurredAt is not commit order. Redis is best effort, not durable replay.
- **Security/authorization:** Header-authenticated active users; existing readable group/Activity permissions at subscribe and delivery; membership loss stops protected delivery. Do not broadcast private domain DTOs indiscriminately.
- **Testing:** Prove after-commit only, no rollback delivery, authorized receive, unauthorized denial and membership-loss revocation. Prove parse/routing once, duplicate suppression, Activity refetch, stale/disposed guards, reconnect subscription recovery and visible UI updates. Add focused checks before broader regression.

Repeat across reconnect/network loss and permission revocation; record candidate identity and evidence.

- **Dependencies:** Existing Chat WebSocket/Redis, PostgreSQL transactions, Activity RSVP/capacity rules, auth, FCM lifecycle and private QA fixtures.
- **Definition of Done:** Reusable architecture reviewed; required backend/Flutter evidence passes; RSVP physical two-device validation passes; reconnect/revocation and known best-effort limits documented; no regression of protected existing behavior.
